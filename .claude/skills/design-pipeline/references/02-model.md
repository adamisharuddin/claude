# Stage 2 — 3D model (SketchUp or Blender)

Claude cannot click inside SketchUp, so the model is **generated by code** from
`spec.json`. That is the point: every change is a spec edit and a re-run.

## Inputs
Brief dimensions, any plan/sketch/photo the user gave (read dimensions off it; for an
object photo use the `image-to-sketchup-dae` or `img2threejs` skills), chosen direction.

## Produce
1. `spec.json` (see `spec-schema.md`) — layout planned by Claude: zoning, circulation,
   furniture placement, joinery, lighting points, cameras.
2. `build.rb` — SketchUp Ruby script. The user's only action, once:
   *SketchUp → Extensions → Ruby Console →* `load "/path/to/build.rb"`.
   It builds groups/components per element, tags (layers) by `tag`, applies
   materials by name/colour, and adds scenes for every camera. Re-running it
   replaces the model, so later changes stay one action.
3. `model.dae` — the same geometry as Collada, importable into SketchUp/Enscape/D5
   without running Ruby.
4. `scene.py` — Blender Python that builds the same scene headless, for stage 3.
5. `previews/` — plan (top orthographic, dimensioned) and axonometric PNGs rendered
   headless, so G2 needs no software on the user's side.

All four outputs come from one generator so they never disagree. Validate per the
spec rules before showing anything.

## Gate G2
Show plan + axo (+ a quick clay render). AskUserQuestion: "Layout OK?" — Approve /
Approve with tweaks (free text) / Try alternative layout. Tweaks → edit spec, regenerate,
show diff image; only re-gate if the change is structural.
